# Catalog readiness

The decisions guide 12 asks every demo to write down. The draft resource is
[`deploy/demoproject.yaml`](../deploy/demoproject.yaml); guide 20 covers onboarding. It has not
been through the platform's `validate-projects` yet.

1. **Session boundary and identity source.** A browser session: the API sets a `crew_session`
   cookie (32 random hex characters, HttpOnly, SameSite=Lax, Secure behind HTTPS) on the first
   request. The platform's sign-in scopes nothing.
2. **What the session identity scopes.** Every Workflow ID: `<task queue>-<session>-<order>`. The
   API builds IDs from the cookie, so one browser can't read, pay for or message another's order;
   Temporal answers not found. The same ID is the store's Idempotency-Key, so ledger rows are
   per order too. The Worker status is shared: every viewer sees the same Worker, which is the
   point of the demo.
3. **Task-queue environment variable, base queue, and how Workflow code inherits the queue.**
   `TEMPORAL_TASK_QUEUE`, base `retail-agentcore`, set as a literal on `api` and `agent`. The
   Workflow starts no child Workflows and uses no other queue.
4. **How Workflow IDs and external records stay distinct across crashable workspaces that share a
   Namespace.** There are no crashable workspaces: the platform never makes a project with a
   serverless component crashable, and the draft says `crashable.enabled: false`. Concurrent
   presenters are kept apart by session-scoped Workflow IDs (2), and the store's ledger rows by the
   same IDs. The member and café data are read-only and shared.
5. **Build and component mapping.** Four builds, each its Dockerfile's last stage: `web`
   (nginx) runs `web`; `api` (last stage `api`) runs `api`; `store` (last stage `store`) runs
   `store`; `agent` (last stage `runtime`) runs the serverless component `agent` (`aws-agentcore`,
   built for linux/arm64 by the platform, `idleSessionTimeoutSeconds: 60`). The Build ID is unset,
   so each commit is a new Worker Deployment Version and pinned orders finish on the version they
   started on.
6. **Public and internal routes.** `/` to `web:http`, behind the platform sign-in. `/store` to
   `store:http`, public (`routes[].public`), because the AgentCore runtime calls it from outside the
   cluster; every route under `/store/v1` checks the bearer token. `web` reaches `api` and `api`
   reaches `store` by Service name (`http://api:8080`, `http://store:8080`). The agent has no route:
   Temporal Cloud invokes its AgentCore endpoint.
7. **Temporal configuration and credential flow.** API key auth (`temporal.auth.mode: apiKey`).
   The API gets `TEMPORAL_ADDRESS`, `TEMPORAL_NAMESPACE`, `TEMPORAL_API_KEY` and `TEMPORAL_TLS`
   from `temporalAccess`; the agent gets the same through the platform's cold-start wrapper, plus
   `TEMPORAL_DEPLOYMENT_NAME` and `TEMPORAL_WORKER_BUILD_ID`. Both read them with the SDK's
   envconfig, config file disabled. No Search Attributes.
8. **Required secrets and external state.**
   - `store-api`, generated by the operator (`generate.properties: [STORE_API_TOKEN]`). `store` and
     `api` list it in `secrets`; the agent reads it with the input ref
     `secrets.store-api.STORE_API_TOKEN`. Nobody needs to know the value.
   - A DynamoDB table (`aws.dynamodb.tables.ledger`, hash key `pk`, TTL on `expiresAt`, 7 days) in
     `STORE_LEDGER_TABLE`, for payments, orders and Stardust awards.
   - Bedrock: `us.anthropic.claude-sonnet-5-5` in `BEDROCK_MODEL_ID`; model access must be enabled
     once per AWS account.
   - Both grants go to `store` and `agent` through one role (`aws.components: [store, agent]`). The
     AgentCore exec role has no network perimeter, so a credential copied out of the runtime could
     reach the ledger table until it expires. The table holds fictional demo payments only.
9. **The smoke-check endpoint.** `GET /healthz` on the host: nginx proxies it to the API, which
   answers 200 when Temporal answers `CheckHealth`. It changes nothing and wakes no Worker.
10. **Known mismatches with the current registry contract, and open items.**
    - **The agent's store URL is a literal.** No platform variable gives a serverless component the
      demo's host, so `STORE_API_URL` names
      `https://retail-agentcore.test.tmprl-demo.cloud/store/v1` in the test copy. The live copy
      needs the live base domain; check it before onboarding.
    - `Strands Agents` is not among the catalog's `aiSdks` examples; the draft adds it.
    - `AGENTCORE_DEBOUNCE_SECONDS` is 30 in the draft (Temporal's sample uses 60), so the Worker
      drains within a minute of the cart; the 60 s idle session timeout then ends the session.
